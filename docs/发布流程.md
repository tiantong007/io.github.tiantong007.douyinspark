# 发布流程（备查，暂不执行）

> 当前状态：仓库与 Release 已发布。本文件记录提交到 LSPosed 官方仓库的步骤。

## LSPosed 仓库的硬性要求

来源：https://github.com/Xposed-Modules-Repo/.github/blob/main/profile/README.md

1. **仓库名必须等于模块包名** → `io.github.tiantong007.douyinspark`
2. **仓库必须有非空 description**（就是商店里显示的模块名）
3. **必须至少有一个 release**
4. release 必须带 apk 附件，且 **tag 名格式为 `VersionCode-VersionName`** → `20004-v2.1.0`

提交入口：https://modules.lsposed.org/submission

> 官方提醒：只改 release 里的 APK 文件不会触发同步机器人，必须"发布 release"这个动作本身。

## 五步

```
① GitHub 建仓库 io.github.tiantong007.douyinspark
   Description: 抖音续火花cc · 抖音自动续火花（支持互动表情）

② push 源码 + README + LICENSE
   README 必须写「基于 WorldMargin/SparkFlame 修改」（Apache-2.0 要求，已写在附录 C）

③ 建 Release
   Tag:  20004-v2.1.0
   Asset: release\douyinspark-arm64-v8a.apk

④ 提交 modules.lsposed.org/submission

⑤ 审核通过后，机器人会镜像到
   github.com/Xposed-Modules-Repo/io.github.tiantong007.douyinspark
```

## 发布前检查表

- [ ] README 有上游链接 + Apache-2.0 声明
- [ ] LICENSE 文件在根目录
- [ ] versionCode 已递增（否则用户收不到更新）
- [ ] 用**同一个 keystore** 签名（换签名会导致老用户无法覆盖安装）
- [ ] README 写明「与上游 SparkFlame 签名不同，同时装需先卸载其一」
- [ ] README 写明「需要 LSPosed 2.x（API 101+）」
- [ ] README 写明「`[STICKER:xxx]` 是本版私有标记」

## 版本号规则

**v2.0.0 起启用独立版本号**，不再沿用上游 `v1.5.x-ccN` 序列（功能集已分叉，继续挂 v1.5.x 会误导）。

```
versionCode = 主*10000 + 次*100 + 修订 + 构建序号
              例：v2.0.0 第 1 次构建 → 20001
                  v2.0.0 第 2 次构建 → 20002
                  v2.0.1            → 20101
versionName = v2.1.0（不带 cc 后缀）
tag         = <versionCode>-<versionName> → 20004-v2.1.0
```

`versionCode` 必须单调递增，否则降级安装失败（`INSTALL_FAILED_VERSION_DOWNGRADE`）。

历史序列（已废弃，仅供追溯）：11107-v1.5.7-cc → 11108-v1.5.7-cc2 → … → 11113-v1.6.0-cc2
