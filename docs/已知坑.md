# 已知坑

## 1. LSPosed 相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 装完新包名模块，LSPosed 里是"未启用" | 只在 `staticScope=false` 时发生 | 本项目 `module.prop` 是 `staticScope=true`，**装完自动启用+勾作用域** |
| 模块不注入 | 目标 app 进程是旧的 | 只需重启**抖音**（`am force-stop` + `am start`），不需要重启手机 |
| 手工改 `modules_config.db` 后仍不生效 | lspd 缓存 + 需要 zygote 重新 fork | 改完必须重启设备（这条路不推荐，优先用管理器 UI） |
| `org.lsposed.manager` 打不开 | 管理器不是普通 app，`monkey` 也拉不起 | 从 `/data/adb/modules/zygisk_lsposed/manager.apk` 手动安装 |

## 2. 配置相关

| 现象 | 原因 | 处理 |
|---|---|---|
| 改了 `spark_config.json` 的 body，App 里显示"未写文案" | App 启动时按 snapshots 重建会话列表，会覆盖部分字段 | 改配置必须**先 force-stop App**，改完再打开 |
| 手动发送提示"跳过：XXX（没有文案）" | 该会话不在 `conversations` 数组里（只存在于 snapshots） | 在 App 里勾选并「移入已选目标」，会写入 conversations |
| 卸载重装后配置全丢 | `/data/data` 随卸载删除 | 卸载前 `su -c cp` 出配置，装完推回（owner 必须改成新 uid） |

## 3. 群聊解禁（本项目的改动）

| 风险 | 说明 |
|---|---|
| 群成员都能看到 | 单聊只有对方，群聊是全员可见（例：「群名(4)」4 个人都看得到） |
| 候选数量暴增 | 35 个快照里含多个群，开总开关后会自动进「已选目标」 |
| 风控 | 多群同模板同时间发，抖音比单聊敏感 |
| 自动发送默认跳过群聊 | `AutoSparkBridge.kt:145` 的 `isGroup -> forced`：群聊只有在「手动移入未燃」（进 `forcedRenew`）时才自动发 |

建议：先只勾 1 个群试，观察 2~3 天再放开。

## 定时唤醒相关（2026-11-17 补）

### `am kill` 关不掉抖音

`am kill` 只杀「可杀的后台进程」。抖音被 monkey 拉起时带 Activity，是前台进程，
`am kill` 拿它没辙（实测 `aweme procs` 仍是 2）。必须用 `am force-stop`。

`force-stop` 会设 `stopped=true`，但下次 monkey 照样能拉起来。

### `am broadcast --include-stopped-packages` 解除不了 stopped

实测：
```
am broadcast -a ...action.WAKE -p PKG --include-stopped-packages
→ Broadcast completed: result=0，但 stopped=true procs=0
```
`FLAG_INCLUDE_STOPPED_PACKAGES` 只保证广播不被丢弃，接收方进程仍然起不来。
唯一能救的是 `monkey`。

### 模块 App + 抖音 双 uid 才能跑通

LSPosed 注入的代码在抖音进程（uid 10238），但 `ConfigProvider` 在模块 App（uid 10276）。
抖音进程读配置走 ContentProvider 跨进程调用，**模块进程必须活着**，否则
`ConfigClient.read()` 静默返回 null，日志表现是「模块配置不可读」或「会话列表未就绪」。

### `su` 必须写绝对路径

模块进程里 `ProcessBuilder("su", ...)` 找不到 —— 环境变量 PATH 里没有 `/system/bin`。
必须写 `ProcessBuilder("/system/bin/su", "-M", "-c", cmd)`。

`-M`（`--mount-master`）是 KernelSU 的全局 namespace 开关，不加会导致子进程
看不见 `/data/data` 下除自己以外的目录。

### 锁屏下 monkey 能拉起抖音且不亮屏

```
input keyevent KEYCODE_SLEEP → mWakefulness=Asleep
monkey -p com.ss.android.ugc.aweme -c android.intent.category.LAUNCHER 1
→ 抖音起来、发完消息、wake 全程保持 Asleep
```

### 测试脚本里的 `date -d` 不可用

toybox `date` 不支持 `-d '+2 minutes'`，会静默输出空字符串，导致目标时间算成 0:0。
用 `awk` 自己算。

### 「等发送完成」不能用文件内容做判据

`spark_last_auto_day` 记的是日期（`2026-11-17`），同一天里抖音被打开过一轮它就已经是今天。
闹钟再响时拿「内容 == 今天」判断，10 秒后就会把还在冷启动的抖音杀掉（实测只活 12.9 秒）。

必须记响铃前的 `stat -c %Y`（epoch 秒），等它变大。见 `docs/定时续火花.md` 第九节。

### 改配置必须先 force-stop 宿主

抖音进程内存里有旧快照，改完 `sed` 再 `am force-stop` 会被回写覆盖。
正确顺序：`am force-stop` → 写文件 → 冷启动。
