## 一、采纳（高优先）

### 1. 贴纸目录动态化（替代硬编码签名 URL）

现状：`app/config/StickerCatalog.kt` 的 `CONTENT` map 硬编码「续火花」content JSON，url 签名 2027-11 到期，且抖音改版/新增表情就要重新抓包。

上游做法（`host/im/StickerCatalog.kt`，84 行，可直接移植）：
- 读 `context.filesDir/keva/repo/imbase_*/strategy_config.sgv`
- 字节级搜 `"interactive_resource_config"` → 花括号配对截出 JSON
- 按 `display_name` / `static_url` / `animate_url` / `biz_type` 建 `Item` 列表，内存缓存

修改方案（保持 `[STICKER:名]` 私有标记不变，用户脚本零改动）：

```
app/config/StickerCatalog.kt   保留 isStickerMark/nameOf/CONTENT（作为兜底）
host/im/StickerCatalog.kt      新增：上游 84 行原样移植（package 行改为 com.worldmargin.autospark.host.im）
host/bridge/AutoSparkBridge.kt 发送链路改为两级查找：
    stickerJson = 宿主侧 host/im/StickerCatalog.items(context).firstOrNull{it.name==名}?.let{拼 content}
              ?: app/config/StickerCatalog.byName(名)          // 兜底：keva 里没有（如「续火花」id=0 的特殊贴纸）→ 用硬编码
```

上游的 content 生成逻辑（`AutoSparkBridge.stickerContentFor`）：取 `static_url` 填进 `url.uri/url_list`，补 `sticker_type=12`。注意上游与我们的 content 结构字段名有差异（我们有 `emoji_type:"lite_emoji"`、`aweType:507` 等，是抓包全量字段），移植时**发送仍走我们的 ImMsgBridge.sendStickerJson 全量 content 组装**，keva 只提供 url/name/biz_type 三个字段，其余字段沿用我们的模板——避免上游简化 content 在个别机型上被抖音拒绝。

配套（可选，95b360a）：keva 解析结果按「文件 mtime」缓存；设置页加「刷新表情目录」入口（清缓存重读）。比上游的「模块更新/抖音更新/过期天数」三开关简单，够用。

### 2. 多段发送（ctx.commit / submit / exit / segment）

上游实现在 `SparkScriptEngine.kt`（+150 行）与 `AutoSparkBridge.kt`（+67 行）。我们引擎无此概念（grep 确认只有 Rhino 的 `Context.exit()`）。

修改方案（按上游 API 面照抄，保证脚本可移植）：

引擎（SparkScriptEngine.kt）：
- `SandboxEnv` 加 `stickers: String = "[]"`（目录 JSON）
- 注入全局：`ctx.commit()` → 切段，返回 `{handle:"seg-N", index:N}`；`ctx.submit()` → 最后一段并结束；`ctx.exit()` → 放弃本轮；`ctx.segment(handle)` → 查段状态
- `renderSegments(script, values, env)` 预览入口：preview 模式返回文本段/贴纸段列表
- 结果回调扩展：`res.segments = [{handle, ok, reason?}]`

Bridge（AutoSparkBridge.kt 发送循环）：
- `rendered.segments.ifEmpty { listOf(SendSegment("text", text)) }`
- 每段独立 `commit/submit`（抖音 IM 的分段 commit 链路，上游已验证），段间带 `old_client_message_id` 防重
- 每会话上限读配置（默认如 3 段），超出合并进最后一段

UI（可选二期）：设置页「发送分段」独立列表页 + 预览页按段展示。一期先只做引擎 + Bridge，设置项给固定默认值。

价值：模板可以「先发一句 + 贴纸 + 再发一句」，这是上游 11-18 刚做完的新能力。

### 3. 权限最小化：删 INTERNET（安全性最大收益）

现状：Manifest 持有 6 个权限（INTERNET / SCHEDULE_EXACT_ALARM / USE_EXACT_ALARM / RECEIVE_BOOT_COMPLETED / SYSTEM_ALERT_WINDOW / WAKE_LOCK）。INTERNET 的唯一消费者是 `AvatarLoader.kt:127 download()`（HttpURLConnection 拉头像）。

上游做法：模块零网络权限；头像/贴纸图由**宿主（抖音进程）下载**，经 `ConfigProvider`（+241 行）推到 `files/sticker/`（生效版）+ `files/sticker.next/`（推送版，整版到齐才并入），读取先 A 后 B；头像按 uid 同步（v1.6.1）。

修改方案（分两步，一步一个版本）：

步骤 A（先做，改动小）：
- `AvatarLoader.download()` 改走宿主侧：hook 上下文里用抖音自己的网络栈拉 URL（抖音有 INTERNET），结果经现有 `AutoSparkBridge` 的宿主→模块通道回传 Bitmap 字节。若宿主侧失败，UI 显示占位图（不闪退）。
- Manifest 删 `<uses-permission android:name="android.permission.INTERNET" />`
- 收益：模块 APK 权限面从 6 → 5，用户审计时「一个模块要网络权限干嘛」的质疑消失

步骤 B（可选二期）：贴纸图/头像本地双段落盘缓存（`StickerImageStore`），彻底离线可用。改 ConfigProvider + 新增 StickerImageStore，约 100 行。

其余 5 个权限评估：
- SCHEDULE_EXACT_ALARM / USE_EXACT_ALARM：定时唤醒必需，保留
- RECEIVE_BOOT_COMPLETED：开机恢复闹钟，保留
- WAKE_LOCK：定时唤醒拉起期间保活，保留
- SYSTEM_ALERT_WINDOW：**核查后大概率可删**（上游 v1.6.0 前后没动它，但我们 grep Manifest 有；需确认是否还有悬浮提示用途，没有就删）

## 二、改造采纳（中优先）

### 4. APK 自校验（防改包/防 hook 伪造）

上游 `ApkFingerprint.kt`（119 行）+ `ContentFingerprint.kt`（37 行）+ `IntegrityManifest.kt`：

- ApkFingerprint：直接读 APK 文件字节解析 Sig Block 42（v2/v3/v3.1 魔数 `0x7109871A/0xF05368C0/0x1B93AD61`），证书 DER → SHA-256。**不走 PackageManager**（可被 hook 改写 signatures）。读不到 v2+ 块 = 校验不通过。
- ContentFingerprint：APK 内指定前缀条目（上游是 `assets/cm6/`、`manual.md`）排序后哈希，对比构建期注入 `BuildConfig.CONTENT_SHA256`。我们对应条目是 `assets/docs/manual.md`、`assets/fonts/`。

修改方案：
- 两个类原样移植（package 改名，PREFIXES 改成我们的条目）
- `build.gradle.kts` 加 contentEntries 计算 + manifest placeholder 注入 CONTENT_SHA256
- 校验时机：只在「宿主进程里 hook 生效前」做一次性校验（ModuleMain.onModuleLoaded），失败仅记 ModLog + Toast 提示「模块可能被篡改」，**不阻断运行**（我们是个人分发，误杀成本高于收益；上游阻断是因为它有正式用户群）
- JNI 混淆 / native syscall：**不采纳**——我们没有 native 代码，为此引入 .so 得不偿失

## 三、不采纳（与本项目分叉决策冲突，理由记录在案）

| 上游能力 | 不采纳理由 |
|---|---|
| CodeMirror 6 编辑器（editor.js/tslibs/completions，离线 1.2MB） | cc2 明确决策「原生 EditText，省 1.2MB」；编辑器是我们最大的体积优势 |
| 标签 UI + `tags: {include, except}` 筛选语法 | cc3 删除标签 UI；若采纳会把批次三要清的包袱又接回来 |
| 宏编辑 UI（MacroEditActivity/FunctionEditActivity） | v2.0.0 决策「引擎保留，UI 移除」 |
| `ctx.emoji` 文本表情面板 | 我们场景只需要「续火花」一张贴纸，面板过重 |
| 更新浮层 | 我们版本发布走 LSPosed 商店镜像，App 内更新提示与商店重复 |
| 贴纸抽屉 StickerBar + PreviewActivity 全套 | 若做多段发送，二期可参考其按段预览渲染，但整页照抄会带回上游 UI 复杂度 |

## 四、执行顺序（与 docs/优化方案.md 的批次衔接）

```
第 1 步（跟批次一一起，同一天）：
    批次一版本对齐 → commit → push → 触发镜像同步

第 2 步（v2.1.3，安全向小版本）：
    3.步骤A 删 INTERNET（AvatarLoader 改宿主拉取）
    3.SYSTEM_ALERT_WINDOW 核查后视情况删
    4.ApkFingerprint + ContentFingerprint（日志级，不阻断）
    → versionCode 20007 / v2.1.3，按新检查表发版

第 3 步（v2.2.0，功能版）：
    1.贴纸目录动态化（keva 解析 + 硬编码兜底）
    2.多段发送一期（引擎 + Bridge，固定默认段数）
    → README「脚本 API」补 ctx.commit/submit/exit/segment 文档

第 4 步（可选二期）：
    2.多段发送 UI（设置页 + 预览页）
    3.步骤B 贴纸图本地缓存
```

**第 2 步执行结果（2026-11-20，v2.1.3 / 20007）**：

| 项 | 落地方式 |
|---|---|
| 删 `INTERNET` | 头像改由宿主推送：`host/im/AvatarCache.kt` 从抖音自己的缓存目录 `files/tc_effect/aweme/720x720/aweme-avatar/` 按 URL 末段找图 → 分批经 `ConfigProvider` 的 `putAvatars`（Bundle，key = uid 的 MD5，≤512 KB/张）落到 `cacheDir/avatars/<md5>.png`；`AvatarLoader` 零网络，只读该目录，调用点第二参数从 avatar URL 改为 `peerUid` |
| 删 `SYSTEM_ALERT_WINDOW` | 全仓核实零引用（悬浮引导是 `PopupWindow`，定时唤醒走 `monkey`），已删；剩 4 个权限：`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` / `RECEIVE_BOOT_COMPLETED` / `WAKE_LOCK` |
| `ApkFingerprint` | `core/ApkFingerprint.kt` 直读 APK Sig Block 42（v2 `0x7109871A` / v3 `0xF05368C0` / v3.1 `0x1B93AD61`），刻意不走 `PackageManager` |
| `ContentFingerprint` | `PREFIXES = ["assets/docs/manual.md", "assets/fonts/"]`（上游是 CodeMirror 的 `assets/cm6/`，我们没有）；构建期由 `app/build.gradle.kts` 的 `contentEntries` 算出 `BuildConfig.CONTENT_SHA256`，与运行时同一口径（实测 APK 内 `3700a78c…` 与构建期一致） |
| 自校验入口 | `core/SelfCheck.kt` 的 `runOnce(context)` 挂在 `SparkSettingsActivity.onCreate`（幂等、daemon 线程、只 `ModLog` 不阻断）；只在模块自己的进程跑（`context.packageName == BuildConfig.APPLICATION_ID`），因为模块代码也注入到抖音进程，那里的 sourceDir 是抖音 APK |

## 五、风险与回归清单

- keva 解析依赖抖音内部存储结构（`imbase_*` 目录名、`strategy_config.sgv`），抖音大版本更新可能失效 → 必须保留硬编码「续火花」兜底（这是我们的私有核心功能，不能断）
- 多段发送动的是 IM 发送链路，回归项：普通文本 / 贴纸 / 文本+贴纸混合 / 每日多次触发 / 定时唤醒全程（锁屏 + 不亮屏）
- 删 INTERNET 后回归项：头像显示、表情目录刷新、文档页（本地 WebView 渲染，无网络依赖，不受影响）
- 自校验的 CONTENT_SHA256 构建注入在 CI 里跑（批次二 2.3 的 workflow），本地 build.ps1 也要同步算，否则本地包启动即告警
