### 2.3 最小 CI（新增 .github/workflows/tag-check.yml）

push tag 时自动校验，20 行：

```yaml
name: tag-check
on:
  push:
    tags: ['*-*']
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: tag 必须是 VersionCode-VersionName
        run: |
          code=$(echo "$GITHUB_REF_NAME" | cut -d- -f1)
          grep -q "appVersionCode = $code" src/app/build.gradle.kts \
            || { echo "::error::tag $GITHUB_REF_NAME 与 build.gradle.kts versionCode 不一致"; exit 1; }
      - name: README 横幅与 versionName 一致
        run: |
          name=$(echo "$GITHUB_REF_NAME" | cut -d- -f2-)
          grep -q "（versionCode $code）" README.md \
            || { echo "::error::README 版本横幅未更新"; exit 1; }
```

（可选进阶：tag 时顺带跑 `gradlew assembleRelease` + `gh release create` 自动上传，把手工 build.ps1 流程也自动化。）

### 4.2 README 是唯一文档（v2.0.0 决策）——保持，但注意

`build.gradle.kts:97-105` 构建时把根 README 复制进 `assets/docs/manual.md` → **README 每次改都会进 APK**。所以 README 修订 = 发版流程的一部分，别在两次发版之间随手改 README（会与商店镜像分叉）。检查表加：README 改动必须随发版一起走。

### 4.3 商店文案（SUMMARY）版本

镜像仓库 `SUMMARY` 决定商店描述，与 README 分开维护。批次一兜底方案里顺手同步。以后发大版本时 SUMMARY 一起更新。
